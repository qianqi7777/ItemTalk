# V2 运行管理

V2 使用现有 PostgreSQL、国内模型服务和本地文件存储。COS、自动备份和邮件告警不作为 V2 启用条件，也不由本流程启用。发布仍使用维护窗口、人工配对备份和隔离恢复验证。

## 启用与授权

将配置保存到服务器现有的受限环境文件，变量格式见根目录 `.env.example`。不要把真实文件提交到 Git。API、Worker 使用相同的 `V2_ENABLED`、`MODEL_PROFILES`、`MODEL_PRICES` 和额度硬上限；密钥、供应商地址和向量模型沿用受限配置。

1. 停写并生成、实际验证数据库与本地资产的配对恢复点。
2. 使用迁移身份执行 `alembic upgrade head`。0010 新增管理、审计、指标及私有缓存表；0011 创建 trigram/HNSW 索引，要求 pgvector 0.8.0 以上。不会自动升级扩展。建索引会消耗 CPU、磁盘和表锁，须计入维护窗口。
3. 设置 `V2_ENABLED=true`，启动受限 API。已有额度计数保留；初始运行配置沿用当前有效环境额度。
4. 由本人提供已注册账号的 UUID，使用受限迁移身份执行一次：

   ```text
   python -m app.admin_cli grant --user-id <已有账号UUID>
   ```

5. 重新登录或刷新能力接口后进入“运行管理”。普通账号访问管理接口返回 403。授权不扩大私人聊天、照片、记忆等数据的读取范围。

撤销管理员使用同一迁移身份执行 `revoke --user-id <UUID>`。API/Worker 无法直接修改成员表。不要为授权临时给予应用超级用户或 BYPASSRLS。

## 可修改配置

管理页面仅修改全局日额度、默认主体日额度、后台业务任务暂停和已验收文本模型方案。修改要求来源校验、幂等键和 `expectedVersion`；版本冲突返回 409，配置和审计同事务提交。额度调整不重置计数，UTC 日结算。

`RUNTIME_GLOBAL_HARD_LIMIT`、`RUNTIME_SUBJECT_HARD_LIMIT` 是服务端硬上限。部署时必须覆盖当前有效额度；不要通过修改硬上限绕过真实验收调用预算。暂停只阻止新顶层业务任务领取，已运行任务、子任务和清理继续处理。

`MODEL_PROFILES` 仅包含方案标识、模型名和 `accepted`。未通过同账号同地域 JSON、SSE、工具调用与质量验收的方案保持 `accepted=false`。管理员只能选择已验收方案，不能编辑地址、密钥或向量模型。已有会话运行和后台任务使用各自的配置快照，新配置只影响新运行。

## 指标与费用

最近一天、七天、三十天统计来自原始样本，P95 不通过平均每日 P95 计算。每次上游尝试分别记数，流式尾部 usage 缺失时保留未知；未配置价格的调用保持未计价。HTTP 首个正文等待时间包含引用核验，供应商首 token 延迟另记。SSE 已发送 200 后的受控错误、中断仍按错误或中断统计。

`MODEL_PRICES` 是服务端 JSON 数组，每项包含 `provider`、`model`、`effective_from`、`currency`、`input_per_million`、`output_per_million`，可选 `min_input_tokens` 和 `max_input_tokens`。输入长度区间包含端点，同一模型取当前日期前最近生效日，重叠或缺失区间不估价。价格单位为每百万 token，估算不等于云账单；折扣、免费额度和供应商最终结算须另核对。历史记录不会因修改价格被悄悄回写。

指标不保存问题、回答、附件地址或密钥。Worker 每轮有界清理过期缓存和超过三十天的明细，原子累加日汇总并保留一年；不新增定时服务。

查询向量缓存按用户、查询摘要、供应商、模型、修订和维度隔离，默认二十四小时；账号删除时清除，不缓存最终个性化回答。

## 并发与回退

Worker 默认并发一。API 两个进程的连接池各最多六，Worker 最多三、迁移最多一，共十六，留四个诊断连接；同一数据库不要额外启动未纳入预算的副本。

回退到 V1 镜像前，在 V2 尚可运行时由现有管理员恢复当前文本方案、解除后台暂停并恢复环境额度：

```text
python -m app.admin_cli reset-runtime --user-id <已有管理员UUID> --expected-version <当前版本>
```

此命令使用现有受限应用配置并逐次校验管理员身份，写入审计，不清零计数。版本冲突须重新读取和审核。随后停止新版本、换回固定旧镜像及旧配置，保留兼容的新表、列和索引，不自动降级数据库。新旧 Worker 不得同时写入。

只有确认新增结构出现不可兼容问题时，才在停写状态使用已验证的数据库、资产及配置配对恢复点。不要覆盖唯一备份。远程执行前必须另外确认最终 SHA、维护影响和回滚清单。
