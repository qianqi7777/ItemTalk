# 运行管理

[← 项目首页](../README.md) · [模型配置](../docs/CONFIGURATION.md) · [发布与维护](MAINTENANCE.md) · [备份与告警](BACKUP_AND_ALERTS.md)

管理界面提供运行指标、额度、后台任务开关，以及文本、图像、语音和向量四类配置。文件名保留 `V2_RUNTIME.md`，方便已有链接继续使用。

> 服务器试用可使用 `staging + local`。COS、定时备份和邮件是独立可选能力，不因开启运行管理而自动启用。维护发布仍要求人工配对备份与隔离恢复验证。

## 启用与授权

1. 准备完整迁移和恢复点。使用迁移身份执行 `alembic upgrade head`，不要仅应用早期 `0010/0011` 后就启用当前应用。
2. API 与 Worker 配置 `V2_ENABLED=true`，以及一致的额度硬上限、模型预设和价格信息。
3. 需要后台新增服务配置时，为两者设置相同且有效的 `MODEL_CONFIG_ENCRYPTION_KEY`。一次生成，保存在受限配置与恢复依据中。
4. 先注册账号，再由受限迁移/运维身份，从后端环境授权该账号 UUID：

   ```text
   python -m app.admin_cli grant --user-id <已有账号UUID>
   ```

5. 重新登录或刷新能力后访问管理入口。普通账号访问管理 API 返回 403。

撤销权限使用同一身份运行：

```text
python -m app.admin_cli revoke --user-id <账号UUID>
```

API/Worker 无管理员成员表直接写权限；不要临时授予它们超级用户或 BYPASSRLS。管理权限也不扩大对私人聊天、照片、记忆的读取范围。项目没有供所有安装共用的默认管理员凭据。

## 管理员能修改什么

| 配置                 | 当前能力                                    | 约束                                   |
| -------------------- | ------------------------------------------- | -------------------------------------- |
| 文本、图像、语音服务 | 新增地址、协议、模型、key，测试后保存并启用 | 各用途独立，协议须匹配用途             |
| 向量服务             | 新增地址和 key，测试后启用                  | 模型、修订、维度和协议固定为服务器预设 |
| 网站日额度           | 全局与默认主体日额度                        | 不超过服务器硬上限，不清空已有计数     |
| 后台任务             | 暂停新顶层业务任务领取                      | 已运行、子任务和清理仍会继续           |
| 服务预设与历史配置   | 启用已保存配置或恢复预设                    | 保留历史配置和审计                     |

运行配置更新包含来源校验、幂等键和 `expectedVersion`；配置与审计同事务提交。409 表示版本冲突，应刷新核对后重试。

## 模型配置的生效方式

详细操作见[模型与服务配置](../docs/CONFIGURATION.md#管理员切换模型)：

```text
选择用途 → 填写配置 → 测试 → 保存并启用 → 核对当前配置
```

测试使用固定合成输入，检查对应协议能力，会消耗真实调用预算。测试通过不是所有型号质量的保证；表单变更或测试过期后须重新测试。

启用影响**新运行与新任务**，进行中的任务继续使用各自快照，无需为日常切换重启服务。保存与启用分开提交，出现“已保存但未启用”时从列表重试启用。

密钥加密保存不回显，变更通过新增配置完成；不要直接替换加密主密钥。`MODEL_PROFILES` 仍支持服务器预设的文本方案，只有标记 `accepted=true` 的方案可选；它不再是唯一的模型管理方式。

向量端点能力测试只验证协议、批量输出和维度等约束，不证明与旧服务的向量空间相同。更换模型或修订不能当成普通换 key 操作。

## 额度与后台任务

- 网站额度按 UTC 日计数，UTC 00:00 对应东八区 08:00。
- `RUNTIME_GLOBAL_HARD_LIMIT` 和 `RUNTIME_SUBJECT_HARD_LIMIT` 是服务器硬上限，必须覆盖当前有效额度。
- 切换模型不会清零计数，也不能解决网站自身已耗尽的额度；供应商余额另行核对。
- 后台暂停只阻止新顶层业务任务领取，不等于完整停写；维护前还需实际停止 API/Worker 和其他写入口。

不要为绕过验收预算而提高硬上限。模型测试、重试、引用核验和扫描转写也会计入相应调用预算。

## 指标与费用

| 指标              | 解释                                                 |
| ----------------- | ---------------------------------------------------- |
| 1 / 7 / 30 天统计 | 来自原始样本，P95 不通过平均每日 P95 计算            |
| 上游尝试          | 每次实际尝试单独计数                                 |
| HTTP 首个正文等待 | 包含引用核验等工作，区别于供应商首 token 延迟        |
| SSE 错误          | 即使 HTTP 已返回 200，后续错误或中断仍按实际结果统计 |
| 缺失 usage / 价格 | 保留未知或未计价，不当成零 token / 零费用            |

`MODEL_PRICES` 为 JSON 数组，字段为 `provider`、`model`、`effective_from`、`currency`、`input_per_million`、`output_per_million`，可加输入长度区间 `min_input_tokens/max_input_tokens`。区间包含端点，同模型使用当前日期前最近生效日；区间重叠或不匹配时不估价。

价格按每百万 token 计算，历史估算不因改价被回写，折扣与免费额度以供应商账单为准。指标不保存问题、回答、附件地址或密钥。Worker 清理超过 30 天的明细、累加日汇总并保留一年，不新增定时服务。

## 并发与缓存

Worker 默认并发一。默认连接预算为 API 两个进程各最多六、Worker 最多三、迁移最多一，共十六，另留诊断空间。增加副本前重新核对实际配置与数据库容量。

查询向量缓存按用户、查询摘要、供应商、模型、修订和维度隔离，默认 24 小时，账号删除时清除；不缓存最终个性化回答。网页研究缓存按实际问题匹配，模型推测不能作为联网证据复用。

## 兼容回退

按[维护手册](MAINTENANCE.md#失败与回滚)审核具体目标版本，不能把“保留兼容新表”理解为任意旧应用都能直接启动。

回退到不支持当前配置的旧应用前：

1. 在当前管理界面把文本、图像、语音、向量恢复到目标应用支持的配置，处理持有新协议快照的任务。
2. 解除后台暂停并恢复经审核的额度，保留已有计数和审计。
3. 停止新 API/Worker，切换固定旧镜像和原配置，保留兼容 schema，不同时运行新旧 Worker。
4. 核对健康、认证、资产、任务和实际模型协议。

现有 CLI 也可由管理员恢复**文本预设、环境额度与后台开关**：

```text
python -m app.admin_cli reset-runtime --user-id <管理员UUID> --expected-version <当前版本>
```

此命令不负责把其他三类已选配置一并恢复；它们需在管理界面分别核对。版本冲突须重新读取，不能盲目重试旧版本号。

跨越 RLS/角色等不兼容边界时，需停写后按已验证的数据库、资产、配置和角色依据配对恢复，不能只换镜像或自动执行 downgrade。不要覆盖唯一备份。
