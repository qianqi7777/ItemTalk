# V1 维护窗口验收与发布

此清单用于需要停写、迁移权限与配对恢复的发布。`requires-maintenance` 继续阻止自动部署；不能为了运行已有发布脚本把标记改成 `expand-only`。所有服务器写操作须先提供具体 SHA、影响、备份和回滚方案并获得确认。

日常备份/失败告警按 [V1备份与告警方案](BACKUP_AND_ALERTS.md)执行：本地7天、南京独立COS桶长期保留、每日上传读回校验、每周临时库恢复。当前仅完成本地实现/Mock验证/模板；真实服务测试与生产启用另需确认。日常在线快照不能替代下述迁移前停写备份。

## 必须先准备的证据

- 最终代码提交、该完整 SHA 的成功 CI，以及同 SHA 的 API、前端和数据库镜像摘要。`Deploy` 继续跳过维护版本镜像发布和服务器部署；独立的 `Maintenance images` 工作流只准备维护镜像及发布配置包，不连接服务器。
- 真实模型、检索、受限 Agent、语音和 COS 的验收报告。单一产品的文字样例、mock 流程和已有测试通过不能替代全部供应商质量验收；中断报告不满足门禁。
- 当前发布路径、数据库 revision、数据库/文件大小、剩余磁盘容量和运行服务状态；只输出必要元数据，不显示环境变量值、账号内容或私有资产内容。
- 数据库、上传文件、原应用配置及角色/权限恢复依据的受限备份。数据库与文件须在同一停写窗口中配对生成，并在隔离目标实际恢复核验。
- 独立管理员、迁移、API、Worker 角色和新配置准备就绪；只有变量名可写入操作记录。API/Worker 无所有权、超级用户或 BYPASSRLS；不得沿用旧应用管理员连接。
- 用户明确确认停写窗口、恢复点以及可接受的失败/回滚时间。

COS 可先使用 `app.cos_probe --real-cos --origin https://49.233.65.195 --report <本轮新报告>` 验证供应商协议。它仅创建本轮带 nonce 的合成对象，检查 CORS/签名/私有读/不可变副本/归档字节回写并清理已核对归属的候选，不修改桶权限/策略/版本/CORS，不访问数据库或模型。成功不代替真实应用上传确认、越权、任务清理及完整配对恢复证据；报告cleanupIncomplete或running不能满足门禁。

`Maintenance images` 只接受本仓库 main 的成功 push CI，手动指定也核对同一完整 SHA 的成功 CI。核验 API、前端、数据库及备份四个摘要镜像可拉取且 OCI revision 等于目标 SHA 后，保存 `release.json`、`image-overrides.env`、`release-config.tar` 及 `release.sha256`；归档只取该提交跟踪的 Compose、SQL、infra，不夹带本地设计文档或生产配置。备份镜像基于同次 API 摘要，额外安装 PostgreSQL 16 客户端并检查其版本及受限 UID 的离线入口。目标 revision 来自镜像内离线 `alembic heads`，不是当前生产 revision。

执行前下载并核对全部校验和，复核 JSON 中的 SHA、CI、revision 与镜像摘要。将审核后的 `image-overrides.env` 保存为本次发布目录的 `.env.image_tag`，继续分开加载服务器受限生产配置。Compose 的 API/Worker/migration 使用同一个 `API_IMAGE`，DB/前端分别用对应摘要；未提供摘要时保留旧 SHA 标签启动方式。摘要记录不会随标签重建而改变，维护操作不得以运行旧 `deploy.sh` 来替代停写/配对恢复流程。

## 停写与备份

1. 显示维护状态，暂停 API、Worker、后台清理和其他写入入口；Nginx 及服务器上其他项目保持运行。核对实际容器状态，不以旧 PID 或记录文件推断已停止。
2. 记录旧发布及镜像摘要，锁定本次维护操作，确认当前没有其他部署。
3. 保存 PostgreSQL custom dump 和本地资产归档、摘要清单、校验和，以及受限的配置与角色恢复依据。备份目录在持久化数据目录之外，不覆盖已有备份。
4. 恢复到本次新建的隔离数据库及空资产目录，核对数据、约束、RLS/所有权/ACL、函数、触发器和文件字节。确认过的资产必须与数据库哈希/大小一致。归档目录列表验证不算恢复演练。
5. 仅在明确的备份恢复点已验证后继续；失败保持维护状态，原数据库、文件和配置不改动。

源存储为 COS 时，使用 `app.restore_check --cos-assets --writers-paused` 的数据库对象清单配对归档；其恢复目标是隔离本地目录及新数据库，须另用独立目标桶验证归档回写、同键字节和新适配器读取。命令只备份数据库登记的当前对象，不备份版本历史或扫描其他项目对象；未登记孤儿对象由独立清理/生命周期策略处理。不能用原 `backup.sh` 的本地目录 tar 代替 COS 对象备份，也不能把本地恢复报告当作目标桶恢复证明。

日常 COS 备份容器可使用 `--cos-assets --online-immutable-assets`，允许源库正常写入，恢复的是导出快照；已确认对象须逐一匹配该快照的大小和哈希，二次对象读取发现删除/改写则失败。它不声称停写，不保证快照后的写入或桶版本历史已备份，不能替代本次维护停写的旧配置/角色/数据库/资产恢复点。每次输出仅包含受控统计，保留受限 dump、归档、清单及校验和。

安装备份 timer 前，核对运维 UID/GID 与 `/opt/itemtalk/backups` 的受限所有权，先在预留容量内运行一次恢复核验；该操作会创建/删除本次临时库并写入备份，仍须确认。脚本不启动/暂停数据库、API或Worker，使用 `--no-deps` 的独立备份容器；管理员密码只在此容器的环境内，备份 COS 凭据可另用只读账号。确认失败告警、保留期限与异地副本方案后才启用 timer，不自行清理旧备份。

## 权限迁移与本地资产转 COS

1. 用管理员在当前数据库预置 `runtime-roles.sql`，使用迁移角色应用迁移，记录新 revision。生产不自动执行 downgrade。
2. 如果原应用使用本地存储，新生产配置改用 COS 前必须复制现有资产。仅修改 `STORAGE_BACKEND` 会使已有照片和官方文件无法读取，不能作为迁移。
3. 在写入及清理仍暂停时，按已验证清单复制到受限 COS 桶，保留原对象键；每个对象验证字节数和 SHA-256。同键已存在且内容不一致必须停止，不得覆盖。未确认上传和待清理对象也应保留清单及到期处理依据。
4. 校验全部已确认资产都能由新存储适配器读取。旧签名和未完成上传的影响须在维护通知中明确；不得通过延长旧签名有效期绕过清理规则。
5. 原本地文件、原配置和配对备份保留到验收和回滚期限结束。COS 复制失败不能清除原文件，也不自动删除已复制对象。

迁移工具为 `uv run python -m app.storage_transfer --assets-directory <原资产目录> --writers-paused --report <新报告文件>`，默认只生成计划。获得具体远程操作确认、验证备份后，才添加 `--apply` 并使用完整 COS 配置实际复制。每次重新核对全部对象，同内容同键可安全复用，冲突或变化立即停止；报告不覆盖已有文件，原数据库和文件不更改。

该工具只接受私有 ACL、未启用/未暂停版本控制及无扩大读取权限策略的桶。版本桶的禁止覆盖头不会提供所需保护，删除也可能保留旧版本；含 Allow 的桶策略须另行访问审查。工具不会关闭版本控制、修改桶权限或删除安全策略。操作凭据须具备读桶版本/ACL/策略、读写目标对象的权限；缺失权限失败后保留源数据。

## 启动与验收

1. 使用固定 SHA 镜像和明确的新配置，先启动受限 API 验证运行角色、健康状态、数据库 revision 和 buildVersion；验证完成前不恢复普通写入。
2. 用专用验收账号核对 `/itemtalk/` 前缀、HTTPS、Secure Cookie、SSE 引用、真实照片确认与读取、记忆确认/撤销、私有说明书、引导暂停重载恢复及高风险拒绝。
3. 启动受限 Worker，核对领取任务、续租、角色隔离和清理；测试删除只作用于专用验收数据，保留其他用户与公共知识。
4. 检查证书有效期与续期、数据库及文件备份、任务积压、受控错误和失败告警。只有最终健康/版本与验收一致，才更新 `current` 并结束维护。
5. 记录执行人、时间、旧/新 SHA、revision、备份位置和验收结果；不记录任何密钥或生产环境值。

## 失败与回滚

- 启用 RLS 后旧应用可能无法认证或访问私有数据。此版本不能只换回旧镜像，也不能使用仅支持兼容迁移的 `deploy.sh` 处理失败。
- 保持新 API/Worker 停止，使用验证过的旧数据库、文件、配置和角色/权限恢复依据配对恢复，再启动旧 SHA。恢复前再次确认目标路径、备份校验和、容量和停写状态，不覆盖唯一备份。
- 回滚后检查旧版本 HTTPS/health、原有资产、认证和任务状态，确认没有新旧 Worker 同时写入。恢复期间产生的专用验收记录按方案处理。
- COS 新对象保留为迁移记录，不自动清空桶；删除或清理另行明确范围并审批。

本文件只准备流程，不执行部署。实际维护命令须在确认服务器与备份现状后形成可审核的操作包；当前仍需 COS、最终真实质量及维护窗口的具体验收证据。
